Ques01: VM hardening kya hota hai?
VM hardening ka matlab hai virtual machine ko secure banana, taki hacker, malware aur unauthorized users uska misuse na kar sakein.
Imagine karo tumne ek Linux server ki VM banayi hai. By default usmein kuch unnecessary services, open ports aur default configurations ho sakti hain.
VM Hardening karke hum un security weaknesses ko reduce karte hain.
VM Hardening mein kya-kya karte hain?
Disable unnecessary services: Jo services use nahi ho rahi hain, unhe band karna.
Close unused ports: Unnecessary network ports ko close karna.
Strong passwords: Weak passwords ko replace karna.
SSH security: Root login disable karna aur SSH access secure karna.
Firewall configure karna: Sirf required network traffic allow karna.
Install security patches: OS aur software ko updated rakhna.
User permissions: Users ko sirf required permissions dena.
Disable unused accounts: Unnecessary user accounts remove ya disable karna. 

Interview mein answer:
"VM Hardening is the process of securing a Virtual Machine by disabling unnecessary services, closing unused ports, applying security patches, configuring firewalls, and implementing strong access controls to reduce its attack surface."

# Jenkins + Docker: Troubleshooting Documentation

## 1. Problem: Incorrect sudoers file permissions

We initially ran:

bash

```bash
sudo visudo -c
```

The output showed:

text

```text
/etc/sudoers.d/jenkins-devops: bad permissions, should be mode 0440
/etc/sudoers.d/vagrant: bad permissions, should be mode 0440
```

Solution: Correct the permissions.

bash

```bash
sudo chmod 0440 /etc/sudoers.d/jenkins-devops
sudo chmod 0440 /etc/sudoers.d/vagrant
```

Verify:

bash

```bash
sudo visudo -c
```

Expected:

text

```text
/etc/sudoers: parsed OK
/etc/sudoers.d/jenkins-devops: parsed OK
/etc/sudoers.d/vagrant: parsed OK
```

## 2. Problem: Bash interpreter mismatch

We tested:

bash

```bash
sudo -u jenkins sudo -n /opt/devops/scripts/install-docker.sh
```

Received:

text

```text
/opt/devops/scripts/install-docker.sh: 4: set: Illegal option -o pipefail
```

Reason: The script uses Bash-specific syntax:

bash

```bash
set -euo pipefail
```

But it was being interpreted using `/bin/sh` (Dash).

Solution: Execute the script explicitly using Bash.

bash

```bash
sudo -u jenkins sudo -n /bin/bash /opt/devops/scripts/install-docker.sh
```

Check the script:

bash

```bash
head -n 5 /opt/devops/scripts/install-docker.sh
```

Expected:

bash

```bash
#!/bin/bash

set -euo pipefail
```

## 3. Problem: Jenkins required a sudo password

We received:

text

```text
sudo: a password is required
```

Reason: The existing sudoers rule authorized direct execution of the script, but not execution through `/bin/bash`.

Initially, our rule was:

text

```text
jenkins ALL=(root) NOPASSWD: /opt/devops/scripts/install-docker.sh
```

We needed to authorize the explicit Bash command.

## 4. Solution: Update Jenkins sudoers configuration

Open the sudoers file:

bash

```bash
sudo visudo -f /etc/sudoers.d/jenkins-devops
```

Replace its contents with:

text

```text
jenkins ALL=(root) NOPASSWD: /bin/bash /opt/devops/scripts/install-docker.sh
```

Save and exit.

Set correct permissions:

bash

```bash
sudo chmod 0440 /etc/sudoers.d/jenkins-devops
```

Validate:

bash

```bash
sudo visudo -c
```

## 5. Verify Jenkins sudo permissions

Run:

bash

```bash
sudo -l -U jenkins
```

Expected authorization:

text

```text
User jenkins may run the following commands on master-node:
    (root) NOPASSWD: /bin/bash /opt/devops/scripts/install-docker.sh
```

## 6. Final execution test

Execute:

bash

```bash
sudo -u jenkins sudo -n /bin/bash /opt/devops/scripts/install-docker.sh
```

This verifies that the Jenkins account can execute the authorized Docker installation script without an interactive password prompt.

## 7. Important security improvements

For a production-quality setup:

- Keep the installation script owned by root.
- Do not allow Jenkins to modify scripts that it executes as root.
- Restrict Jenkins administrators and pipeline permissions.
- Avoid granting unrestricted sudo access to Jenkins.
- Review privileged operations before executing them through pipelines.
